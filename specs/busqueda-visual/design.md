# Design

Python internal HTTP service: stdlib ThreadingHTTPServer bound 127.0.0.1:8001 by default, shared X-API-Key, no public CORS, /health GET and /embeddings POST JSON {images:[base64]} -> {modelId, embeddings:[[512 floats]]}. Validate content length, image bytes/format/pixels, hash, finite vectors and normalization. One inference at a time, bounded thread admission, socket timeout. Decode EXIF, RGB, resize224 BICUBIC, ImageNet mean/std. Load ONNX once, CPU threads2. Never fetch caller URLs or save query bytes. Pinned model download helper for EC2, no model in Git.

NestJS BusquedaVisualModule; POST /api/v1/busqueda-visual/avistamientos JWT CIUDADANO, multipart fotos and required especieId. Validate species name Perro/Gato and bytes. No new Node dependencies. IA_SERVICE_URL + IA_SERVICE_TOKEN config optional together (disabled if absent); local env configured without revealing tokens. Internal fetch timeout and response validation. Remote photo fetch only HTTPS res.cloudinary.com, redirect rejected, 5MiB stream cap, timeout. Migration new avistamiento_embedding(photo_id UUID, model_version varchar100, vector real[512], created_at), compositePK + cascading photoFK. Only active public sightings/users used, recheck before return. Similarity per report = mean across query photos of best cosine over that report's available photos; deterministic sort, top5. Public result {modelo,aviso,fotosConsultadas,fotosNoProcesadas,resultados:[{similitud,avistamiento:{public fields only}}]}. No owner IDs/storage keys/vectors exposed. Two global searches and one per user at a time, 429 when busy. Mobile timeout180sec. Indexing batch bounded; 503 when Python unavailable,400 bad image/filter,413 limit,422 too broad,empty valid.

Flutter reusable PhotoSelection/pickPhotos and species selection. Feature busqueda_visual model/service/screen. Entry in main app bar visible throughout authenticated citizen app, screen keeps selected photos on errors, disables mutations during request, clears old results when input changes; mounted guards; loading/empty/error/retry, ranked cards navigate to existing SightingDetailScreen (map/contact/chat). Uses existing http,image_picker only, no mobile env changes.
